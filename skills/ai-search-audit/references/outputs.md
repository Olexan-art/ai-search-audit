# Outputs: what each file holds

Read this when the user asks for the data (the Markdown or the JSON), or what the report or the export contains.

- `report.html`: one self-contained page (inline CSS and one small script, favicons as data URIs, a content security policy that blocks every network request, every piece of page text escaped), light by default with a dark theme on the toggle, English, Ukrainian and Polish, safe down to 375 px. Summary first: a headline built from the findings, the severity counts, three cards (robots can find it, the text, the brand and questions), the three findings to review first, and the places in the document with the selected one beside them; every technical detail is in one closed section, *All checks and technical details*. Judgement findings carry an "Agent's judgement · <model>" badge, and a note says that brand, reviews and questions are one model's view. It opens in English and in the light theme; `#lang=uk` opens it in Ukrainian, `#lang=pl` in Polish and `#theme=dark` in the dark theme (for example `report.html#lang=pl&theme=dark`).
- `report.md`: the same audit in Markdown, in English: the status, the biggest problems, every problem with its code, place and layer, the page map as a list, the checklist, the bots, the language versions, where the text goes, and what was not checked.
- `export.json`: `getlooploop/ai-search-audit@1`. Every finding with `code`, `severity`, `area`, `owner`, `layer`, `judgement` (`agent`, `model`, or `null`), `label` (en, uk), `where`, `map` (zones and strip rows), `passages`, `evidence` and `rules` (each `{ name, url }`), plus the tiles, the checklist, the page map, robots, sitemap, llms.txt, languages, alternates, links, structured data, `keyword`, `writingPatterns`, `generatedText` (the last block: Pattern score, marker words, swap test, per passage), `localeFacts`, `judgement` (the files as validated), the reading's waterfall, `notChecked` (every cap) and `notMeasured`.
- `reading.json` (`getlooploop/ai-search-audit-reading@1`): everything read in step 1, so step 6 can be rerun offline.

The readable source is `scripts/` in the repository, built into `dist/` with esbuild; tests: `npm test` in the skill folder of a repository checkout.
